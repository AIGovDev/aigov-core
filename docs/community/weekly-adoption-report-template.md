# Weekly adoption report

Copy for each reporting week; attach the GitHub Actions metrics artifact rather than changing its source snapshot.

- **Week ending (UTC):** YYYY-MM-DD
- **Automated snapshot artifact:** URL or `unavailable`
- **Report owner:** maintainer

## Adoption and contributions

- Stars / forks / non-bot contributor accounts: copy observed counters and timestamp.
- Open issues / PRs: record the API count and any notable external contribution separately.
- PyPI downloads (rolling day/week/month): copy aggregate values; do not call them unique users.
- Release-asset downloads: observed value; source archives are excluded.
- GitHub views / clones: exact recent count or `unavailable` with reason.
- Hugging Face Space: public URL, verification timestamp, and available views/likes/duplications. If not published or analytics are unavailable, say so explicitly.

## External distribution and assurance

- Catalog submissions: one line per target with PR/issue URL, submission date, current status, and whether accepted. Internal drafts are not submissions.
- Independent review: request/application URL or receipt, date, status, named external reviewer if appointed, and scope. Keep “not contacted,” “applied,” “accepted,” “in progress,” and “completed” distinct.
- Funding: program and application state, deadline, award or matching-fund condition. Never record a plan as an application or an award as cash received.

## Inquiries and launch activity

- Potential customer inquiries received this week: count; source; organic or campaign-attributed; stage. Keep identities and messages in the private tracker.
- Partnership inquiries: count and source; do not infer a partnership from outreach or a reply.
- Launch/promotion: date, channel, post URL, and any paid spend. If no promotions ran, write `none`.
- Organic signals: unsolicited external issue/PR, independent mention, or inbound usage question, with public URL where possible.

## Interpretation

Write two or three sentences separating observed changes from promotion activity. Do not infer installs, active users, production use, customer conversion, security assurance, or regulatory compliance from proxy metrics. Retain `unavailable` and `not measured` values as written.
