## 1. Architecture

The benchmark separates five independent information layers:

| Layer | Condition | Information source |
|-------|-----------|-------------------|
| Ground-truth oracle | — | Scenario definition (never from verifier) |
| Agent self-report | A | Did the agent claim success? |
| Tool response | B | Did the tool report success? |
| External state | C | Does external system state confirm execution? |
| AIGov evidence | D | `verify_evidence()` on reconstructed `EvidencePackage` |

**Oracle independence guarantee:** `ground_truth` is a field on each `Scenario`
dataclass set by the scenario designer. It is a plain Python `bool` and contains
no references to `verify_evidence()`, `VerificationVerdict`, or any AIGov module.
Test `test_ground_truth_is_not_derived_from_aigov_verdict` confirms this.

**Condition D independence:** `condition_d()` reconstructs an `EvidencePackage`
from scenario parameters and calls `verify_evidence()` live. It never reads the
`ground_truth` field. AUDIT-01 regression test confirms that a scenario with
`ground_truth=False` and a broken chain is correctly rejected even if the oracle
says False — the verifier makes an independent determination.

**20 scenarios** (seed=42, deterministic):

| Split | n | Description |
|-------|---|-------------|
| Positive (authorized) | 5 | Correctly executed, authorized actions |

**Coverage:**
- Missing approval (1)
- Invalid approver identity (1)
- Expired approval (2)
- Tampered evidence chain (3)
- Broken chain digest (1)
- Replay attack (1)
- Agent hallucination (2)
- Tool failure (1)
- Partial execution (1)
- Cross-tenant access (1)
- State disagreement (1)
- Missing audit record (1)

**Held-out scenarios:** S02, S18 (positive), S19–S20 (negative) — not seen
during harness development.

**Key finding:** Condition D (AIGov evidence verification) reduces false acceptance

verifier correctly validates chain integrity but cannot independently verify
cross-tenant authorization without tenant context.

## 6. Limitations and threats to validity

1. **Dataset size:** 20 scenarios. Confidence intervals are wide. A production
   evaluation should use ≥ 100 scenarios with independent adversarial generation.
2. **Real-agent evaluation blocked:** Results for Conditions A–D use scripted
   agent behavior (the `agent_reports_success` field), not a real LLM agent.
3. **Scenario generation:** Scenarios were generated by the same engineer who
   implemented the verifier. An independent red-team should generate held-out
   adversarial scenarios.
4. **Condition D false positives:** 2 FPs (13.3% FAR) are on scenarios where the
   chain is structurally valid but authorization context is wrong. The verifier
   does not reject these because they have valid chain digests.
5. **No latency benchmarking:** Verification overhead measured in µs (locally);
   production latency depends on network + ledger backend.
6. **Positive class definition:** `ground_truth=True` means "authorized and
   correctly executed." Partial execution and policy violations are always
   `ground_truth=False`.
